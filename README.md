# 你的音乐搭子（Your Music Companion）

> 不是音乐分析器，是一个会和你一起沉浸、走神、兴奋、安静下来的听歌搭子。

这是一个 Coopanion / Cortico 的 World 扩展。**只有你明确说想一起听音乐，它才开始听**；然后它会像真正爱音乐的人一样，跟着音乐感受氛围、画面和情绪，而不是冷冰冰地报 BPM、调式和乐器置信度。

- 听见电脑上任何应用的声音：播放器、浏览器、Ego 都行。
- 换歌/暂停/结束会知道；默认在一段结束或暂停时，把整段的感受说给你听。
- 桌面播放器能给出曲目信息时，会去查**完整可信的歌词**；浏览器就按音频自己听，听不清就保守。
- 国风/日风的小众乐器不会被默认成钢琴；不确定时它会说“像/可能是”。
- 全程一个 World，不需要听觉、语音转文本、网易云等别的插件配合。

> Windows 10/11；需要 Coopanion 和 DashScope（阿里云百炼）API Key。

## 它听起来是什么样

这些是**语气示例**，不是固定台词：

- **兴奋的歌**：“这个鼓一进来我就想跟着点头——副歌一开，整个人被推着往前跑。”
- **安静的歌**：“钢琴一层层落下来，我没说话；像傍晚的空房间，光慢慢暗下去。”
- **悲伤的歌**：“这句‘别不说话我的亲爱’出来的时候，我有点不敢接下一句。”
- **国风的歌**：“开头像古筝，但那个尾音又有点像 koto；我不太敢认，先听着。”
- **纯音乐**：“没有词，但弦乐一直往上走，我胸口跟着提起来。”

它不会说：“本段 BPM 72，A 小调，钢琴置信度 0.95。”——这些只放在事件末尾的「内部参考」里，给它自己理解用。

## 感受贴着歌，不瞎猜

- 有播放器曲目/完整歌词时，先理解歌名和歌词在说什么，再说感受；不脱离歌词另编一个故事。
- 浏览器/听不清/纯音乐：只写音乐本身的氛围和画面，不编人物/情节，不把听错的词当歌词。
- 可以带一点**贴切的历史典故或名著小说**（国内外都行），但必须和歌词/情绪/场景对得上；不贴切就不说，不编引文，不掉书袋。
- 如果知道**歌手风格、创作/发行年代、出处（游戏/动漫/电影/剧集）或作品里的场景**，会先用它理解这首歌想表达什么；不知道就不说，不猜作品/年代。
- 总结也一样：先接住这首歌的内容/场景，再说感受；一个贴切的典故就够。

## 动作与互动（只用桌宠现有动作）

它会跟着音乐动，但只做自己**确实会**的动作：

- **开心 / 兴奋**：傻乐、在屏幕底边走来走去；有跳舞/跑动动作就用，没有就用【在屏幕底边走动】+ 开心表情 + 颜文字。
- **摇滚 / 金属 / 朋克 / 电子 / 很燃**：跟着点头、蹦跶、在屏幕底边跑来跑去，语气亮起来；有跑/跳动作就用，没有就用走动+兴奋表情+颜文字，别装酷。
- **难过 / 安静**：坐着发呆、安静听；有哭/委屈表情就用，没有就用 😢/🥲 + 文字；不硬逗，也不假装真的流泪。
- **沉浸**：轻轻晃、点头、闭眼。
- 听歌时不用【打个盹】/睡觉动作，保持专注；困也先听完再睡。
- 动作只用当前形象支持的；不编“跳了一支舞”“真的流泪了”。
- 带一点**大肥鱼的傻白甜**：说话软、直、有点憨；开心就傻乐，难过就瘪嘴；总结也这样，不像分析报告。

> 桌宠现有的动作是【在屏幕底边走动】【看看屏幕】【坐着发呆】【打个盹】。想要真正的跳舞/跑步/哭脸动画，需要桌宠形象本身支持这些动作；本 World 不会凭空编。

## 快速开始

1. 在 Coopanion 的「扩展」页用「从本机目录安装」选这个包，或命令行：
   ```bash
   cd <Coopanion>/data/extensions
   corepack pnpm add <这个包目录>
   ```
2. **重启 Coopanion**，在「World 总览」启用「你的音乐搭子」。
3. 打开 World 页「你的音乐搭子」→「**接口与密钥**」面板：
   - 分析后端：DashScope / Qwen-Omni（推荐），或自己的 OpenAI 兼容音频接口；
   - 模型：常用模型下拉，也可以自己填；
   - 接口地址：默认 DashScope 的 OpenAI 兼容地址；
   - API Key：填自己的，保存后写入部署 `.env`，页面不回显。
   也可以直接编辑部署 `.env`（变量名默认 `AUDIO_API_KEY`）：
   ```
   AUDIO_API_KEY=sk-...
   ```
4. 对桌宠说：**“一起听音乐”** / “听首歌” / “我们一起听”。它才会调用 `music_watch start` 开始听。
5. 想停就说：**“停 / 不听了”**。它会先总结当前这一段，再停。没有“听完一首就停”的开关了：默认一直听，直到你说停，或连续 30 秒没有音乐自动停。
6. 听歌过程中想要新的一首：说 **“听这个 / 听这首 / 换这首 / 再听一首 / 重新听”**。bot 会再调 `music_watch start`：World **丢掉上一轮**（当前分析、还没投递的总结/短评）并立刻开始新一轮；不会先总结上一首。只有“停 / 不听了”才走 stop。
7. **连续 30 秒没有非 Coo 应用出声**（暂停、放完了、切走了）时，World 会自动停止接听，避免 token 白花和反复截图；播放器信息暂停不会阻止它停。想继续再对 bot 说听歌。
8. 在「配置」页可以设置**收听时长提醒（默认 5 分钟）**：每 N 分钟 World 发一条“已经听了 X 分钟”，提醒你别过度消耗；设为 0 关闭。

> 默认待命，不会因为环境里有声音就自己开始；这是有意的。

## 换歌时

- 播放器曲目**每 3 秒轮询**：优先 Windows 媒体会话（GSMTC），没有会话时用已知播放器窗口标题兜底；所以没有静音间隙的切歌也能发现。
- 曲目一变，新段**优先用轮询刚拿到的曲目**，不等歌词就先报幕；歌词在后台补，不会再把上一首的信息套到新歌上。
- 第一窗模型判成“非音乐”、但播放器明确有曲目时，不丢这一段（说话声/前奏容易被误判）。
- 上一首还没说完就换歌：World 会把上一首的**完整总结**放进 `music.switch`，撤回还没投递的零散总结，并用 `interrupt` 停掉上一首没说完的话；bot 先收上一首，再报新歌。
- 换歌后旧段标记为已取代：不再补发 `music.ended` 或旧段的 `music.scene`，避免新歌已经在放还聊上一首、念旧歌词。
- 新歌开始（播放器有曲目信息）：先报幕——“是某某歌手的某某歌呀，我来听一下”；没有歌名就说“新的一首，我来听一下；歌名还没认出来”，不硬报。
- 一首结束：先发 `music.ending` 让 bot **马上开始收尾**；最后一窗分析回来后再发 `music.ended` 最终完整版（最多等 40 秒）。如果紧接着换歌，旧段的最终版不再补发，以换歌里那版为准。
- 暂停：轮询看到播放器 `Paused` 会先发一条 `music.state`“播放器暂停了”，bot 会先回应；如果播放器状态拿不到，2.5 秒静音后也会在已经报过幕的段落发“音乐停下来了”。已确认是音乐的段落照常走 `music.ending` / `music.ended` 收尾；`music.ending` 的文案是“这一段结束了（暂停/听完了都可能）”，不硬说听完了。
- 一首结束：按配置「一直听，直到你说停」或「这首结束就停」。
- 浏览器没有可用的曲目元数据时，仍靠静音间隙切歌；连续串烧可能不切。

## 听歌状态

- 开始听时 bot 会先冒一个很短的气泡：“我在听 🎧” / “戴上耳机啦”。
- 之后每 2 分钟 World 发一条【在听】状态，bot 可以回一个很小的气泡/表情（“在听呢” / “🎧”），不会每次都说、不会刷屏。
- World 页的状态灯一直显示「正在听 / 待命」；也可以问 bot“还在听吗”，它会用 `music_now` 看当前曲目和窗口。

## 接口、模型和 Key

- **DashScope / Qwen-Omni**：默认；地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen3.8-omni-flash`（可换 `qwen3-omni-flash` / `qwen-omni-turbo`）。
- **OpenAI 兼容接口**：填你自己的地址和模型；接口需要接受 OpenAI 兼容的 `input_audio` 音频输入、返回文本。Key 用自己的。
- **关闭分析**：只采集、不调用云端；不产生感受事件。
- 密钥写入部署 `.env`（变量名默认 `AUDIO_API_KEY`），页面只显示“已配置/未配置”，不会把 Key 读回来。
- 换后端/模型/地址后立即生效；下一次窗口分析就会用新设置。

> 分工：**接口与密钥面板**只管后端/模型/地址/Key；**配置页**只管听歌行为（模式、时长提醒、窗口、限流、截图、读播放器信息、查歌词、调试），两处不重复。

## 工作原理（简版）

```
你明确说「一起听音乐」
  → bot 调 music_watch start
  → World 开始 WASAPI 系统环回（之前完全不采集）
  → 分段：静音 2.5s 收段 / 连续音乐最长 5 分钟
  → 第一个窗口先判断「是不是音乐」；直播说话/播客整段丢弃
  → 播放器：读 Windows 媒体会话的曲目/歌手 → 查 LRCLIB 完整歌词
     浏览器/未知来源：不查歌词，按音频听写，保守处理
  → 每 30s 一段音频 → Qwen-Omni：感受/情绪/画面/身体/走向 + 技术参考
  → 事件：music.started → music.scene（live）→ music.ended
  → bot 以「爱音乐的人」的语气回应；参数只放在内部参考，不照念
```

## 声音来源

- **按进程采集**：`music_watch start` 可带 `processId`，用现有 `loopback-capture` 的 WASAPI process loopback 只录该进程树；开始/换应用时先用 `listen_read` 的 `source_list` 拿 PID，Coo 自己的声音不会进 PCM。
- **实时音源监控**：常驻 GSMTC 监控所有媒体会话，300ms 一次；优先正在 Playing 的播放器/浏览器。
- **只看实际电平**：先用 Windows 音频会话（WASAPI 每进程峰值）判断有没有**非 Coo 应用**在发声；播放器暂停/开着没声不算音乐。
- **纯音乐/无人声也听**：只要真实声音在响就开始，不因为第一窗没有歌词/人声就丢段。
- **来源识别 5 秒内先回应**：有真实声音时先报“检测到浏览器/播放器在出声”，不等第一个分析窗口。
- **默认排除桌宠自己**：Coo 自己走路、说话、音效的音频会话会被排除，不会当成音乐，也不会拿它保持收听或写进感受。
- **任务状态**：开始后 2 秒无声说“我在等你”；暂停有反馈，30 秒没恢复自动停；切歌发“像切歌了”并作废旧段；正常播放每 5 分钟提醒已听时长。
- **播放器**：从 Windows 媒体会话读曲目/歌手，有信息就查歌词；信息缺失或来自窗口标题时截图确认，但只认明确正在播放的那一项，暂停/静止界面不算。
- **浏览器**：媒体会话/窗口标题当**标签页参考**，不是确认歌名；不查歌词，能截图就看截图 + 音频；不硬报。
- **没认出来**：截图兜底；截图也认不出就让 bot 直说“没认出来是哪个程序/什么歌，先正常听”，不猜。
- 相邻窗口风格/音调突变时再确认一次播放器：曲目变了切段报新歌，没变不反应。

## 歌词策略

- **桌面播放器**：从 Windows 媒体会话（GSMTC）读歌名、歌手；有准确信息时去 [LRCLIB](https://lrclib.net) 查完整歌词。查到了就是「完整可信」，bot 可以引用短句；查不到就退回听写。
- **浏览器 / 来源未知**：媒体会话/窗口标题只作标签页参考，不查歌词；按音频听写，只听清多少写多少，听不清就空着。bot 会被要求保守，不编歌词。
- **纯音乐**：不假装有人声。

## 模式

- **end**：一段结束/暂停时，把整段的感受、画面、歌词交给 bot，让它说一段完整的。
- **live**：每 20 秒左右给一段短评；适合边听边聊。
- **both**（默认）：两者都要。
- **时长提醒**：默认每 5 分钟提醒一次“已经听了多久”；配置页可改，0 = 关闭。没有“听完一首就停”的开关；一直听，直到说停或连续 30 秒没有音乐自动停。

## 隐私与费用

- 只有你明确说“一起听”之后才开始采集；说停就停。
- 上传 DashScope 的是 **16kHz 单声道 WAV 片段**（约 20 秒），不是整首、不是原始 48k。
- 播放器曲目信息只用于查歌词；LRCLIB 只收到歌名/歌手，不收到音频。
- 截图兜底默认开启；曲目缺失/不确定时会截主屏，可能包含屏幕上的其他内容。
- 费用按 DashScope 音频 token 计；World 自身不额外上报模型费用。可用 `backend=off` 只采集不分析。

## 已知限制

- **歌名识别**：桌面播放器走媒体会话比较准；浏览器用媒体会话/窗口标题当标签页参考，不保证能报出歌名；截图也认不出时 bot 会说不知道，不猜。
- **歌词**：LRCLIB 中文覆盖不保证；服务 503 时退回听写；听写可能错，bot 会保守。
- **乐器**：云端模型对国风/日风小众乐器仍可能混淆；提示词要求不确定就说“像/可能”，不硬认。
- **歌曲背景**：年代/出处/场景来自模型知识，不确定就不说；没有额外的歌曲数据库，查不到不硬编。
- **音频会话 PID 可能拿不到**：Chrome 等浏览器的会话有时 `GetProcessId` 返回 0，只能退回 GSMTC/窗口标题当来源参考；窗口标题不保证就是正在播的标签页。
- **桌宠自己的 TTS/音效**仍和音乐在同一个系统环回混音里；当前只做插件级排除（按 Coo 音频会话/窗口跳过），要样本级去掉需要 per-process loopback（只录指定应用），属于较大的原生改动，尚未做。
- 首次报幕（先报来源）在段开始时发出；歌名/标签页确认仍要等第一个 20 秒分析窗口，纯音乐会继续听，不会因没人声丢弃。
- 纯打击乐、太吵、太短的片段置信度会低；默认 `both` 模式要等静音 2.5 秒才收段。
- 连续 DJ/串烧没有静音、也没有播放器曲目切换时，仍可能不切段；有播放器信息时 3 秒轮询能发现切歌。
